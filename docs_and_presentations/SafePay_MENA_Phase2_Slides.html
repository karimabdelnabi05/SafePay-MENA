That deployment used Scam Signal and customer intervention. SafePay has different signals and has not measured these outcomes.

SafePay's implementation focus

Selective investigations

Routine payments avoid extra calls; elevated risk prompts the agent to select relevant evidence.

Multiple journeys, one decision workflow

New-phone setup, takeover, card misuse, suspicious transfers and travel use a shared evidence model.

Visible reasons and controlled decisions

Policy limits agent actions, records missing evidence, and supports repeatable evaluation.

Final technical summary / IT and cybersecurity
Technical architecture and evidence boundaries

Adaptive investigation. Enforced policy. Inspectable outcomes.

01 / Interface

Web app + FastAPI

Session, setup, payment review, cancellation and evaluation.

Bank facts and payment release are simulated.
02 / Risk + agent

Local screen + Gemini

Routine bypass. Function-calling loop chooses and observes one tool at a time.

No scenario labels sent to the model.
03 / Network access

Nokia Network as Code

CAMARA adapter; fixed hosts, validated responses, bound OAuth state.

Approved simulator subjects only.
04 / Final decision

Deterministic policy

Evidence-based disposition, missing-data handling and stored result.

In-memory SQLite demonstration store.

SIM Swap   /   Number Verification   /   Device Swap
Roaming   /   Reachability
